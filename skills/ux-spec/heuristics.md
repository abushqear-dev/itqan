# Usability heuristics for the screen check

Use these with the pinned Web Interface Guidelines (`${CLAUDE_PLUGIN_ROOT}/vendor/web-interface-guidelines/guidelines.md`) when checking each wireframe. Based on Jakob Nielsen's ten usability heuristics, written as questions for one screen.

1. **Status:** does the screen always show what is happening (loading, saved, failed) and what state each item is in?
2. **Real-world words:** does it use the glossary's words, not system terms?
3. **Control and undo:** can the user back out of every action, and is there confirmation or undo before anything destructive?
4. **Consistency:** do the same actions look and work the same on every screen, using only the chosen components and tokens?
5. **Error prevention:** are invalid choices prevented (disabled, constrained inputs) before they can be made?
6. **Recognition over recall:** is everything the user needs visible here, without remembering it from another screen?
7. **Efficiency:** is the key task for this screen reachable in the fewest steps, with one obvious primary action?
8. **Minimal design:** is every element on the screen needed for its stories?
9. **Error recovery:** does each error message say what went wrong and how to fix it, next to the field, with all errors shown at once?
10. **Help:** where a rule is not obvious (a deadline, a limit), is it stated before the user hits it?
